## 2. 项目背景与目标

"拼豆"是一款面向拼豆手工爱好者的 C 端工具 + 社区 App，结合 AI 生图能力提供：

- **M1 注册登录**：手机号、微信、Apple、游客四种登录方式；
- **M2 照片转拼豆**：上传照片由 AI 转换为拼豆图纸（含色号、坐标）；
- **M3 论坛**：帖子、评论、点赞、收藏、关注、话题；
- **M4 经典拼图模板**：模板浏览、收藏、下载；
- **M5 色号推荐**：基于 MARD 色卡推荐合适的拼豆颜色组合。

同时配套**后台管理系统**，覆盖用户、内容（帖子/评论/举报/敏感词）、模板、运营（Banner/专题/推送）、统计、系统配置、MARD 色号、拼豆工具等核心模块。

## 3. 总体技术架构

### 3.1 架构风格

采用 **Clean Architecture（整洁架构）+ 分层架构**，后端代码组织遵循"依赖倒置"，高内聚、低耦合：

```
┌─────────────────────────────────────────────┐
│ 表现层   Pindou.Api  | Pindou.Admin.Api     │  (Controller / Filter / DTO)
├─────────────────────────────────────────────┤
│ 应用层   Pindou.Application                  │  (Service Interface / DTO / 业务编排)
├─────────────────────────────────────────────┤
│ 领域层   Pindou.Domain                       │  (Entity / Enum / 领域事件)
├─────────────────────────────────────────────┤
│ 基础设施层 Pindou.Infrastructure             │  (DB / Cache / 外部服务 / 仓储实现)
├─────────────────────────────────────────────┤
│ 公共层   Pindou.Shared                       │  (工具类 / 扩展 / 通用特性)
└─────────────────────────────────────────────┘
```

依赖方向自上而下、单向：`Api → Application → Domain ← Infrastructure`，`Shared` 不依赖业务层。

| 层 | 技术 |

## 5. 各层职责与依赖

### 5.1 Domain 层

**职责**：

- 定义业务实体（聚合根、值对象）；
- 维护枚举类型（UserStatus、DiagramStatus、OrderStatus 等）；
- 定义仓储接口（`IRepository<T>`）；
- 领域事件与领域服务（可选，本期不强制）。

**约束**：

- 不引用任何外部 NuGet 包（除 SqlSugar 的 `SugarTable` Attribute 标注外，避免引入业务语义）；
- 不引用 Application / Infrastructure / Api / Shared；
- 不包含任何 IO 操作（DB / Redis / HTTP）。

**关键目录**：

```
Pindou.Domain
├── Common/
│   ├── BaseEntity.cs           # 雪花ID基类
│   ├── UuidEntity.cs           # GUID基类
│   └── IEntity.cs              # ISoftDelete / IMultiTenant
├── Enums/
│   └── Enums.cs                # 全部枚举集中管理
└── Entities/
    ├── User/                   # User / Token / Device
    ├── Creation/               # Diagram / ColorInfo / DiagramTask
    ├── Community/              # Post / Comment / Like / Favorite / Follow / Topic
    ├── Template/               # Template / TemplateCategory / TemplateFavorite / ...
    ├── Member/                 # Member / Order / MemberProduct
    ├── Messaging/              # Message / MessageSetting
    ├── Operation/              # Banner / OperationTopic / SpecialTopic / PushRecord
    ├── Statistics/             # DailyUserStats / DailyContentStats / ...
    ├── System/                 # SystemConfig / MardColor / BeadKit / SensitiveWord / Report
    └── Admin/                  # AdminUser / Role / OperationLog
```

### 5.2 Application 层

**职责**：

- 定义数据传输对象（DTO）：输入 / 输出 / 视图模型；
- 定义 Service 接口（`IAuthService`、`IDiagramService` 等）；
- 编排跨聚合的业务用例（Application Service）；
- 通用类型：`ApiResponse<T>`、`PagedResult<T>`、`BizException`、`ErrorCodes`。

**约束**：

- 不直接访问数据库或 Redis；
- 仓储的调用通过 Infrastructure 注入；
- DTO 与 Entity 通过 AutoMapper（可选）或手工映射，禁止直接返回 Entity。

**关键目录**：

```
Pindou.Application
├── Common/
│   ├── ApiResponse.cs
│   ├── PagedResult.cs
│   └── BizException.cs
├── DTOs/
│   ├── Auth/      Creation/   Community/   Template/   Member/
│   ├── Messaging/ Operation/  Statistics/  System/     User/    Admin/
└── Interfaces/
    └── (与 DTOs 一一对应)
```

### 5.3 Infrastructure 层

**职责**：

- 实现 Application 中定义的 Service 接口；
- 提供仓储实现（基于 SqlSugar）；
- 集成 Redis、OSS、SMS、Push、AI 等外部服务；
- 初始化数据库（Code First 建表 + 种子数据）；
- 提供 `IServiceCollection` 扩展以注册所有服务。

**关键目录**：

```
Pindou.Infrastructure
├── Data/
│   ├── PindouDbContext.cs          # SqlSugar 客户端
│   └── SeedData/DataSeeder.cs      # 角色 / 管理员 / 色号 / 会员产品 / 配置
├── Repositories/Repository.cs      # 通用仓储
├── Cache/RedisCacheService.cs
├── Options/Options.cs              # 8个配置类（Database/Redis/Jwt/Sms/Wechat/Push/Ai/Storage）
├── ExternalServices/
│   ├── AI/         (阿里云通义万相)
│   ├── Sms/        (阿里云短信)
│   └── Storage/    (本地 + 七牛云)
├── Services/
│   ├── Auth/        Creation/    Community/    Template/    Member/
│   ├── Messaging/   Operation/   Statistics/   System/      User/      Admin/
└── DependencyInjection/InfrastructureServiceCollectionExtensions.cs
```

### 5.4 Shared 层

**职责**：

- 提供跨层共享的工具方法、扩展方法、Attribute、Helper；
- 不引用任何业务层（Domain / Application / Infrastructure / Api）；
- 可被任意层引用。

**包含**：

- `Utilities/CryptoHelper.cs`：MD5 / SHA256 / AES / Bcrypt 封装；
- `Utilities/JsonHelper.cs`：JSON 序列化、SnowflakeId、OrderNoHelper；
- `Utilities/ValidationHelper.cs`：手机号 / 身份证 / 邮箱 / 脱敏；
- `Attributes/PermissionAttribute.cs`：后台权限码 + 操作日志特性；
- `Extensions/Extensions.cs`：String / DateTime / Enum / Collection 扩展。

### 5.5 Pindou.Api（移动端 API）

**职责**：

- 对外暴露移动端 HTTP 接口；
- 通过 JWT 鉴权（双 Token 机制）；
- 引入 Swagger / Serilog / CORS；
- 注册全局异常过滤器 `GlobalExceptionFilter` 与认证过滤器 `AuthFilter`；
- 启动 `DiagramGenerationBackgroundService` 后台任务（消费 AI 生图队列）。

**关键模块**：

- Controllers：`AuthController`、`UserController`、`DiagramController`、`CommunityController`、`TemplateController`、`MemberController`、`MessagingController`；
- Filters：`GlobalExceptionFilter`、`AuthFilter`；
- BackgroundServices：`DiagramGenerationBackgroundService`。

### 5.6 Pindou.Admin.Api（后台 API）

**职责**：

- 独立部署、独立数据库（`pindou_admin.db` / `pindou_admin` Schema）；
- 启用 `AdminAuthFilter`：验证后台账号 + 权限码（基于 `PermissionAttribute`）；
- 启用 `OperationLogFilter`：自动记录写操作日志。

**关键模块**：

- Controllers：`AuthController`（带图形验证码）、`SystemController`（管理员 / 角色 / 日志）；
- Filters：`AdminAuthFilter`、`OperationLogFilter`、`GlobalExceptionFilter`。

## 6. 关键设计模式

### 6.1 通用仓储模式

```csharp
public interface IRepository<T> where T : class, new()
{
    Task<T?> GetByIdAsync(object id);
    Task<List<T>> GetListAsync(Expression<Func<T, bool>>? where = null);
    Task<T> InsertAsync(T entity);
    Task<int> UpdateAsync(T entity);
    Task<int> DeleteAsync(object id);
    Task<PageResult<T>> PageAsync(int page, int size, Expression<Func<T, bool>>? where);
}
```

所有 Service 通过 `IRepository<T>` 注入，减少模板代码并保证一致性。

### 6.2 JWT 双 Token 机制

| Token | 有效期 | 用途 |
| --- | --- | --- |
| `access_token` | 2 小时 | 携带在 `Authorization: Bearer` 头中访问业务接口 |
| `refresh_token` | 30 天 | 仅用于在 access 过期时换发新 Token；不可直接访问业务接口 |

刷新逻辑：客户端在 `401` + `code=4011` 时调用 `/api/auth/refresh`，后台校验 refresh 有效性后颁发新的 access 与 refresh（refresh 滚动续期）。

### 6.3 BCrypt 密码哈希

统一使用 `BCrypt.Net-Next`，`workFactor=11`（开发可降为 10 以加快速度）。后台与移动端共享同一哈希函数。

### 6.4 雪花算法 ID

通过 `SnowflakeIdHelper` 生成 64 位 Long ID。用于订单号、消息 ID、评论 ID 等需要高并发唯一的场景；用户表采用 UUID（出于分布式友好与隐私考虑）。

### 6.5 AI 生图同步 / 异步分流

- 当拼豆颗数 ≤ 5000：同步调用阿里云通义万相，5s 内返回结果；
- 当颗数 > 5000：写入 `DiagramTask` 队列表，立刻返回任务 ID；由 `DiagramGenerationBackgroundService` 后台消费、回调更新状态；
- 客户端通过轮询 `/api/diagram/task/{id}` 或 WebSocket（可选）获取进度。

## 7. 数据库设计要点

详细字段见《数据库设计说明书 v1.0》。本节仅摘要与框架相关的设计：

| 主题 | 说明 |
| --- | --- |
| 主键策略 | 用户/Token 类用 UUID；业务表（帖子、订单、消息）用雪花 Long；后台 AdminUser 用 Long |
| 软删除 | 实现 `ISoftDelete`（`IsDeleted` 字段）；仓储 `GetList/Delete` 默认过滤 |
| 多租户 | `IMultiTenant`（预留字段 `TenantId`），本期固定 1 |
| 审计字段 | `CreatedAt / CreatedBy / UpdatedAt / UpdatedBy`，由仓储自动填充 |
| 时间统一 | 数据库全部使用 `timestamp with time zone`（PG）/ `TEXT` ISO8601（SQLite） |
| 索引 | 唯一索引：`(phone)`、`(wechat_union_id)`、`(order_no)`；普通索引：`(user_id, status)`、`(created_at)` 用于分页 |
| 复杂字段 | `Diagram.ColorInfo` 存 JSON 文本（PG `jsonb`、SQLite `TEXT`） |
| 图片字段 | 全部存 URL（OSS/七牛/CDN），不存二进制 |

数据库初始化策略：

1. **开发**：SqlSugar `InitTables` 启动时自动建表 → `DataSeeder` 灌入种子数据；
2. **生产**：使用 `deploy/sql/init.sql` 手工建库（PostgreSQL），Schema 与表结构与 SqlSugar 实体保持一致；后续 DDL 通过迁移脚本管理。

## 9. 安全设计

| 项 | 措施 |
| --- | --- |
| 密码 | BCrypt(`workFactor=11`)；禁止明文存储与日志输出 |
| Token | JWT + HS256；密钥从 `JwtOptions.Secret` 注入；access 2h / refresh 30d |
| 防刷 | 短信验证码：同号 1 分钟 1 条，1 小时 5 条上限；登录失败 5 次锁 15 分钟 |
| 防注入 | SqlSugar 参数化；管理后台输入统一过 XSS 过滤 |
| HTTPS | 生产强制 HTTPS（`app.UseHttpsRedirection`） |
| CORS | 仅放行已知前端域名 |
| 权限 | 后台接口使用 `PermissionAttribute` + 角色-权限码映射 |
| 操作审计 | 后台 `OperationLogFilter` 记录写操作（操作人、IP、UA、参数摘要） |
| 文件上传 | 后端校验扩展名 / MIME / 大小；存至 OSS，URL 走 CDN；头像需 AI 鉴黄（接入阿里云内容安全） |

### 11.2 本地开发

```bash
# 1) 启动基础服务
docker compose up -d pindou-db pindou-redis

# 2) 启动移动端 API
cd src/Pindou.Api
dotnet run

# 3) 启动后台 API
cd src/Pindou.Admin.Api

```

也可直接执行 `bash deploy/scripts/dev.sh` 一键拉起。

### 11.3 CI/CD 流水线（推荐）

1. **CI**：PR 触发 → `dotnet build` + `dotnet test` + `npm run lint` + `npm run build`；
2. **Build**：构建多架构镜像（`linux/amd64`、`linux/arm64`），推送至阿里云容器镜像仓库；
3. **Deploy**：Tag 触发 → 滚动更新 API 与 Admin API，Admin Web 直接替换静态资源；
4. **Smoke**：自动调用 `/health` 与登录冒烟用例；
5. **Rollback**：保留最近 5 个镜像版本，异常一键回滚。
