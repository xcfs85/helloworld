## 1. 系统概述

### 1.1 项目背景

拼豆是一款面向 C 端手工爱好者的 AI 拼豆图纸生成工具，核心价值主张：**用 AI 1 分钟把照片转拼豆图纸，让新手也能完成自己的第一个作品**。

产品定位：
- **工具属性**：照片转拼豆图纸 + 色号推荐
- **社区属性**：论坛分享 + 模板库
- **商业属性**：会员订阅 + 电商导流

## 6. 安全设计

### 6.1 认证与授权

```
认证流程
─────────
1. 客户端存储 access_token (内存) 和 refresh_token (安全存储)
2. 每次 API 请求携带 Authorization: Bearer {access_token}
3. API 网关验证 token 有效性
4. token 过期前 10 分钟自动用 refresh_token 刷新
5. refresh_token 过期引导重新登录

授权模型
─────────
- 基于角色的访问控制 (RBAC)
- 接口级权限校验
- 数据级行级权限(用户只能操作自己的数据)
```

### 6.2 安全措施

| 安全项 | 实现 |
|--------|------|
| **传输安全** | HTTPS + TLS 1.3 |
| **数据加密** | AES-256 加密敏感字段 |
| **API 鉴权** | JWT + 签名防篡改 |
| **防刷** | 限流 + 设备指纹 + 行为分析 |
| **内容安全** | AI 审核 + 人工复审 |
| **隐私保护** | 最小化收集、隐私协议、注销权 |
| **风控** | 异地登录提醒、异常检测 |

## 10. 监控与运维

### 10.1 监控体系

```
监控体系
─────────
1. 基础设施监控
   ├── 服务器 CPU/内存/磁盘
   ├── 网络流量
   └── 数据库性能

2. 应用监控
   ├── API 响应时间
   ├── 错误率
   └── 业务指标

3. 业务监控
   ├── 用户注册数
   ├── 生成次数
   └── 社区活跃度

4. AI 监控
   ├── 推理延迟
   ├── 成功率
   └── 准确率(抽检)
```

### 10.2 告警策略

| 级别 | 场景 | 响应时间 |
|------|------|----------|
| P0 | 服务不可用 | 5 分钟 |
| P1 | 核心接口延迟 > 1s | 15 分钟 |
| P2 | 错误率 > 5% | 30 分钟 |
| P3 | 指标异常 | 2 小时 |
