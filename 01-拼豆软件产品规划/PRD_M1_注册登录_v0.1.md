## 1. 背景与目的

### 1.1 背景
注册登录是 APP 使用的第一步,直接影响用户首次体验、留存与转化。拼豆软件面对的是 C 端手工爱好者(主力 22-30 岁女性),她们的特征是:
- 决策周期短,反感复杂流程
- 对隐私敏感,但愿意用微信/手机号快捷登录
- 经常用 iOS(Apple 审核强制要求 Apple ID 登录选项)
- 偶发场景使用,需要快速二次登录

### 1.2 目的
1. **降低注册摩擦**:30 秒内完成首次登录
2. **提升注册转化**:游客到正式用户的转化率 > 60%
3. **多端多场景适配**:iOS / Android / 微信生态全打通
4. **建立用户体系**:为后续会员、电商、社区提供身份基础

### 1.3 MVP 范围
- **包含**:手机号验证码、微信一键登录、Apple ID 登录、游客模式、退出登录、协议确认
- **不包含**(V1.0 再说):找回密码(改用验证码)、多设备管理、实名认证

## 3. 注册登录方式

### 3.1 方式总览

| 方式 | 优先级 | 适用端 | 实现复杂度 | 备注 |
|------|--------|--------|------------|------|
| **手机号 + 验证码** | P0 | iOS / Android | 低 | 主力方式,覆盖最广 |
| **微信一键登录** | P0 | iOS / Android | 中 | 国内必选 |
| **Apple ID** | P0 | iOS 必选 | 中 | Apple 审核强制要求 |
| **游客模式** | P0 | iOS / Android | 低 | 引导注册,提升转化 |
| 邮箱密码 | V1.0 | iOS / Android | 中 | 海外用户基础 |
| 微博 / QQ | V1.0 | iOS / Android | 中 | 锦上添花 |

### 3.2 各方式详细流程

#### 3.2.1 手机号 + 验证码

**流程**:
```
[输入手机号] → [获取验证码] → [输入 6 位验证码] → [勾选协议] → [进入首页]
```

**规则**:
- 手机号:11 位中国大陆手机号(1[3-9]xxxxxxxxx)
- 验证码:6 位数字,有效期 5 分钟
- 同一手机号 1 分钟内只能发 1 次,1 天内最多 10 次
- 同一 IP 1 天内最多 50 次(防刷)

**防刷策略**:
- 图形验证码(第 3 次失败后触发)
- 阿里云/腾讯云短信防刷服务

#### 3.2.2 微信一键登录

**流程**:
```
[点击微信登录] → [调起微信授权] → [用户确认] → [获取 unionid + openid] → [进入首页]
```

**实现**:
- iOS:集成微信 OpenSDK
- Android:集成微信 OpenSDK + 配置签名
- 服务端:用 unionid 关联用户体系

**首次 vs 再次**:
- 首次:弹窗确认授权,获取 unionid + openid + 昵称 + 头像
- 再次:静默登录(只要 unionid 在库里就过)

**绑定手机号**:
- 微信登录后,系统可建议绑定手机号(防微信封号丢账号)
- 绑定弹窗可在"我的 - 账号安全"中关闭
- 不强制(MVP 阶段,后续运营可加奖励引导)

#### 3.2.3 Apple ID 登录

**流程**:
```
[点击 Apple 登录] → [调起 Apple ID 授权] → [用户选择"隐藏/分享"邮箱] → [获取 user_id] → [进入首页]
```

**实现**:
- iOS:Sign in with Apple(必须)
- 服务端:校验 Apple 签名,生成内部用户体系

**重要:Apple 审核要求**
- 如果 APP 提供微信/微博/QQ 等第三方登录,**必须同时提供 Apple ID 登录**
- 否则审核被拒

**用户隐私保护**:
- 用户可选择"隐藏我的邮箱"——APP 收到的是 Apple 提供的虚拟邮箱
- 此时建议引导绑定手机号,以便后续联系

#### 3.2.4 游客模式

**流程**:
```
[首次进入] → [进入游客模式] → [可试用 1 次生成] → [第二次提示注册] → [注册后保留数据]
```

**规则**:
- 游客可使用核心功能:1 次完整生成(不消耗免费额度,单独计数)
- 第二次点击核心功能:弹窗引导注册
- 游客期间产生的图纸:本地保存,注册成功后合并到云端

**防滥用**:
- 设备指纹 + 同一设备 1 天只能注册 1 个账号
- 游客会话有效期 7 天,过期需重新进入

## 4. 协议与隐私

### 4.1 协议展示

**触发时机**:
- 首次注册前
- 协议更新时(需重新同意)

**协议清单**:
- 《用户协议》
- 《隐私政策》
- 《儿童信息保护规则》(若有 14 岁以下用户)

**展示方式**:
- 复选框(默认未勾选)
- 文字可点击,弹窗展示协议详情
- 必须勾选才能注册

### 4.2 隐私合规要点

| 法规 | 要求 | 我们的实现 |
|------|------|------------|
| **个人信息保护法** | 用户明确同意,最小化收集 | 注册时勾选同意;不收集非必要信息 |
| **数据安全法** | 加密存储,境内存储 | OSS 加密;阿里云国内节点 |
| **App 隐私清单** | 第三方 SDK 披露 | 微信/Apple/极光等 SDK 在隐私政策中列明 |
| **注销权** | 用户可注销账号 | "我的 - 账号安全 - 注销账号"功能 |
| **数据导出** | 用户可导出自己的数据 | V1.0 再说 |

### 4.3 用户协议关键条款

- **账号所有权**:账号归用户所有,但需遵守社区规范
- **生成图纸版权**:归用户所有,APP 保留公开展示权(需在协议中明确)
- **用户上传内容**:用户保证拥有版权,APP 不承担审查义务,但有下架权
- **禁止行为**:刷量、发布违规内容、侵犯他人版权
- **免责声明**:APP 不对用户间纠纷负责

## 5. 用户体系设计

### 5.1 用户 ID 体系

| 字段 | 类型 | 说明 |
|------|------|------|
| **user_id** | string(主键) | 内部唯一 ID(如"u_xxxxx"),系统自动生成 |
| **unionid** | string | 微信开放平台 unionid(微信用户) |
| **openid** | string | 微信 openid(单 APP 内) |
| **apple_user_id** | string | Apple ID user_id |
| **phone** | string | 手机号(AES 加密存储) |
| **email** | string | 邮箱(V1.0 再说) |

**关联逻辑**:
- 同一用户可绑定多个登录方式
- 首次登录创建用户,后续登录用 unionid/手机号匹配
- 同一手机号/unionid 只能注册 1 个账号

### 5.2 用户信息

**基础信息**(注册时收集):
- user_id
- 昵称(可从微信/Apple 获取,或用户自定义)
- 头像(同上)
- 注册时间
- 注册方式(phone/wechat/apple)
- 手机号(可选,仅手机注册时有)
- 设备信息(用于安全风控)

**扩展信息**(用户主动填写,V1.0):
- 性别 / 年龄 / 城市
- 拼豆经验(新手/熟手/达人)
- 兴趣标签

### 5.3 登录状态管理

**Token 体系**:
| Token | 用途 | 有效期 |
|-------|------|--------|
| **access_token** | API 调用鉴权 | 2 小时 |
| **refresh_token** | 刷新 access_token | 30 天 |
| **device_token** | 设备唯一标识(推送用) | 长期 |

**续签机制**:
- access_token 过期前 10 分钟,客户端自动用 refresh_token 续签
- refresh_token 过期,需重新登录

**多设备登录**:
- MVP:支持 3 设备同时在线
- 超出后:踢出最早设备(可配置)
- V1.0:用户可管理"我的设备"列表

## 7. 安全与风控

### 7.1 风险场景

| 风险 | 等级 | 应对 |
|------|------|------|
| **短信轰炸** | 🔴 高 | 限流(同手机/同 IP)+ 图形验证码 + 阿里云防刷 |
| **黑产批量注册** | 🔴 高 | 设备指纹 + 行为分析 + 实名(V1.0) |
| **账号被盗** | 🟡 中 | 异地登录提醒 + 强制改密 |
| **微信封号** | 🟢 低 | 引导绑定手机号 |
| **协议拒签** | 🟢 低 | 明确展示,必选 |

### 7.2 风控策略

**注册风控**:
- 同设备 1 天最多注册 1 个账号
- 同手机号/IP 异常时弹图形验证码
- 设备指纹 + 手机号 + IP 多维度判定

**登录风控**:
- 异地登录(距离 > 1000km)推送通知
- 异常设备登录要求二次验证

**短信防刷**:
- 60s 间隔限制
- 单手机号 1 天 10 次上限
- 接入云厂商防刷服务

## 8. 数据结构与接口

### 8.1 核心实体

interface User {
  user_id: string;                    // u_xxxxx

  device_id: string;
  device_model: string;
  os_version: string;

}

## 12. 埋点需求

| 事件 ID | 事件名 | 触发时机 | 关键属性 |
|---------|--------|----------|----------|
| AUTH_001 | 进入登录页 | 首次进入 | entry(冷启动/退出后/超时) |
| AUTH_002 | 选择登录方式 | 点击登录按钮 | method(phone/wechat/apple/guest) |
| AUTH_003 | 输入手机号 | 输入完成 | phone_length |
| AUTH_004 | 获取验证码 | 点击获取 | success(bool) |
| AUTH_005 | 输入验证码 | 输入完成 | code_length |
| AUTH_006 | 协议勾选 | 勾选/取消 | is_check(bool) |
| AUTH_007 | 登录成功 | 登录完成 | method, is_new_user, cost_ms |
| AUTH_008 | 登录失败 | 登录失败 | method, error_code, error_msg |
| AUTH_009 | 退出登录 | 点击退出 | - |
| AUTH_010 | 游客转化 | 游客转正式用户 | from_visitor_count |

**关键漏斗**:
- 进入登录页 → 选择方式 → 完成登录 → 进入首页
- 各环节转化率是核心指标

### 14.2 状态机

```
[APP 启动]
   ↓ 检测登录状态
   ├── 已登录 ─→ [首页]
   └── 未登录 ─→ [登录页]
                  ↓
   ┌──── 手机号 ─→ [输入手机号] ─→ [验证码] ─→ [协议] ─→ [首页]
   ├── 微信 ─→ [微信授权] ─→ [协议确认] ─→ [首页]
   ├── Apple ─→ [Apple 授权] ─→ [协议确认] ─→ [首页]
   └── 游客 ─→ [游客首页] ─→ [引导注册] ─→ [首页]
```

### 14.3 名词解释

| 术语 | 解释 |
|------|------|
| **unionid** | 微信开放平台统一 ID,跨 APP 关联 |
| **openid** | 微信单 APP 内 ID |
| **JWT** | JSON Web Token,用于 API 鉴权 |
| **access_token** | 短时访问凭证(2 小时) |
| **refresh_token** | 长时刷新凭证(30 天) |
| **设备指纹** | 基于设备硬件信息生成的唯一标识 |
